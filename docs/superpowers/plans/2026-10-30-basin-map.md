# Basin Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An interactive MapLibre map on the ungaged page: click a stream, get the basin and its regression quantiles.

**Architecture:** A build-less Streamlit custom component (`map_component/index.html`, MapLibre from a CDN, the component protocol by hand) returns click events to `ungaged_ui.render()`, which fills the existing inputs and, for context-menu actions, runs the existing estimate path or a new delineate-only path. The basin polygon comes from a new `SiteEstimate.basin_geojson` field in flowfreq v0.18.0. Pure geometry (point-in-state, coordinate rounding) lives in `map_geo.py`.

**Tech Stack:** Streamlit ≥ 1.40 (`st.segmented_control`, `st.query_params`), MapLibre GL JS 5.6.0, flowfreq v0.18.0, pytest + `streamlit.testing.v1.AppTest`.

**Spec:** `docs/superpowers/specs/2026-10-30-basin-map-design.md`

## Global Constraints

- Modules at the repository root; `map_component/` is a package directory because `declare_component(path=...)` serves a directory. No `app/` subdirectory (CLAUDE.md).
- No computation in this repo: the polygon comes from the library; the only geometry here is point-in-polygon and rounding.
- Type hints on every signature; NumPy docstrings on public functions; no bare `except:`; no `print()`; `logging.getLogger(__name__)`.
- `black` + `isort` per `pyproject.toml`; run `uv run make check` (Windows: venv on PATH) before every commit.
- Only `https://` URLs in `index.html`; MapLibre pinned to one version string.
- Dependency pin: `flowfreq @ git+https://github.com/pinhead001/flowfreq@v0.18.0` — never `main`.
- Streamlit floor rises to `streamlit>=1.40.0` in `requirements.txt` (for `st.segmented_control`).
- Performance: the component is called once per run with `key="basin_map"`; the JS diffs args; a left click causes one rerun and no library call; panning/zooming never reaches Python.
- Mode names are exactly `"dem"`, `"night"`, `"green"`. Event actions are exactly `"point"`, `"delineate"`, `"estimate"`.

## Review Focus

1. A click in the Aleutians west of 180° (Attu, 52.9°N 173.2°E) must resolve to `AK` — Alaska's MultiPolygon straddles the antimeridian. Test in Task 2.
2. A component value that is not a well-formed event (missing `lat`, wrong types, unknown action) must be ignored with a `logger.warning`, not crash the page. Test in Task 7.
3. A click whose `state_at` code is not among the jurisdiction selectbox's options (ocean → `None`, or a code outside `JURISDICTIONS`) must fill lat/lon and leave the jurisdiction unchanged; writing an invalid option into the selectbox's session-state key raises. Test in Task 7.
4. An estimate whose `basin_geojson` is `None` (a cache entry from before v0.18.0) must show the quantile table with no basin, no GeoJSON download, and no exception. Test in Task 8.
5. Delineate in a jurisdiction StreamStats does not serve (`UnsupportedRegionError`, a `ValueError`) must surface as `kind == "input"` with the library's message. Test in Task 6.
